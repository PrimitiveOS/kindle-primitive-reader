# Core reading controls compared with KOReader

This audit compares Reader 0.1.6 and the subsequent dictionary changes with KOReader v2026.07.1 at commit `9192014d8bd82a91dc1012473be0f238dedfdb54`. It covers controls used while reading. The evidence combines full 1264 × 1680 Oasis 3 reference frames, the tagged Lua handlers and the Rust paths that consume an action. Proposed acceptance checks below remain open until each passes. ## Opening Contents at the reading position

Both the upper Navigation tab and lower Contents button open the list containing the current section. The authored 48-chapter EPUB test opens Day 38 through each control, browses to the previous list page and confirms that the book and its location history stay at Day 38. On a page with multiple publisher headings, Reader identifies the first heading on that page. Between headings it identifies the last preceding one. The same rule applies to PDF outlines and enabled custom contents. Entries with missing targets in the open chapter do not claim the reading position. The same headless test accepts a local long EPUB through `READER_TEST_CONTENTS_EPUB`, selects the middle Contents row and compares all 1264 × 1680 pixels after each return. It uses a temporary profile and saves screenshots only with the authored default fixture. ## Dictionary navigation checks

The desktop tests create two StarDict dictionaries with three definitions of the same headword. They drive the reading app through the same input and rendering interfaces used by the Kindle. [Test fixtures and input sequences](../src/app/dictionary_panel/tests.rs)

| Interaction | Observed on desktop |
| --- | --- |
| Hold a word in an EPUB and open Dictionary | The first exact or case-folded result appears over the original page. Results lists both dictionaries, including the two distinct entries from the second source. Each row opens its own definition. [Result chooser](screenshots/dictionary-sources.png) |
| Scroll and find a word in the longer definition | A vertical swipe scrolls text. A horizontal swipe changes result. The on-screen keyboard searches the displayed entry, and the forward page key reaches the second occurrence near the end. [Search result](screenshots/dictionary-find.png) |
| Hold the word under the search highlight | A second lookup opens. Looking up a missing word from there creates a third level. Two taps on Back restore the earlier result and search highlight with an identical framebuffer. [Nested result](screenshots/dictionary-nested.png) |
| Open Wikipedia from a result, then close | The confirmation sheet uses the dictionary headword, including its capitalization. Opening the sheet starts zero network jobs. Closing restores the dictionary framebuffer. |
| Close the original lookup | The selected EPUB source range, page position and framebuffer match the starting state. A separate PDF test compares the document page, each selected word rectangle and the framebuffer after a nested lookup. |

The screenshots use the authored Field Notes EPUB and test dictionaries. The KOReader Oasis reference contains personal reading material. This round of automated verification ran on the desktop.

## Implementation order

1. **Selection, dictionary and note navigation.** Start with a linked note and two small dictionaries in an authored EPUB. Compare the action surface, each nested back step, the exact anchor, the selected quotation and saved result state. Repeat the selection subset on embedded PDF text and OCR.
2. **Landscape and bottom typography.** Make viewport transforms and input geometry agree before adding more controls. Compare four orientations, RTL spread order, type size, word spacing and maximum expansion using the same pages.
3. **Contents, book map and footer.** Give each consumer the same effective chapter list, test custom and publisher outlines, then add depth, chapter-length and progress preferences. Check sparse outlines and mixed front matter.
4. **Provider and system verification.** Run the path matrix on EPUB, PDF and DjVu. Capture each visible overlay using an authored book. Include callbacks, exact saved locations, framebuffer checks and separate observations for physical buttons and e-ink refresh. A screenshot alone cannot establish persistence or gesture behavior.

## Documented behaviors

The Documents picker labels unsupported formats, oversized files and recognized protected
AZW containers. Damage inside an otherwise supported publication can first become
visible on opening a chapter. An upper swipe opens the upper menu by default and can
be configured to show both bars. [Reader instructions](../README.md#reading-on-kindle)
