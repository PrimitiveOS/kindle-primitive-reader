# Core reading controls compared with KOReader

This audit compares Reader 0.1.6 and the subsequent dictionary changes with KOReader v2026.07.1 at commit `9192014d8bd82a91dc1012473be0f238dedfdb54`. It covers controls used while reading. The evidence combines full 1264 × 1680 Oasis 3 reference frames, the tagged Lua handlers and the Rust paths that consume an action. Proposed acceptance checks below remain open until each passes. [KOReader menu order](https://github.com/koreader/koreader/blob/v2026.07.1/frontend/ui/elements/reader_menu_order.lua) · [Reader source inventory](koreader-source-inventory.md)

The custom footer also includes a selectable local clock. Optional minute-boundary refresh defaults Off, pauses during sleep and resumes on wake; the automated Mac workflow and screenshot are recorded at [current-time-footer.png](screenshots/current-time-footer.png). Kindle acceptance remains open.

Custom footer items now follow KOReader's **Icons**, **Letters**, and **Compact** symbol modes. Icon mode draws native vector symbols, so it does not depend on a device font containing private-use glyphs. The Mac workflow verifies mode cycling, settings persistence, and item reordering; the [footer capture](screenshots/footer-item-symbols.png) and [settings capture](screenshots/footer-item-symbols-settings.png) show the result. Kindle foreground acceptance remains open.

## Searching annotations

KOReader’s bookmark search starts with page bookmarks, highlights and notes enabled. A highlight carrying a note belongs to the Notes category. Its selected passage and its written note are both searchable. The upper Search menu and the lower Bookmarks list now open the same Rust form. It uses the document-search matcher, accepts an empty query to browse the enabled categories, and returns to the same query and filters when the results list closes. A result opens the bookmark, the anchored EPUB selection or the PDF region. **Previous location** returns to the source. [KOReader search controls](https://github.com/koreader/koreader/blob/v2026.07.1/frontend/apps/reader/modules/readerbookmark.lua#L1525-L1612) · [KOReader annotation matching](https://github.com/koreader/koreader/blob/v2026.07.1/frontend/apps/reader/modules/readerbookmark.lua#L1680-L1690) · [Reader search implementation](../src/app/annotation_search.rs)

## Tapping a saved highlight

Tapping highlighted text opens the saved annotation over the current page. If several marks cover the same spot, Reader shows the passages and their note or highlight icons. Select a row to read the note or manage the highlight. Long notes can be paged with the controls or the Kindle page buttons. Edit, extend and removal use the selected mark. Removing a note keeps its highlight. Tapping outside or choosing Close returns to the same viewport. Links inside a highlight retain priority, including when the same tap falls inside a corner assigned to a different action. Both reading engines use the actual rectangles drawn on screen, including fixed-page annotations at high zoom and on subsequent pages of a selection. [Overlap chooser](screenshots/overlapping-highlights.png) · [Note over the document](screenshots/tapped-note.png) · [Rust interaction tests](../src/app/saved_highlight_popup_tests.rs)

KOReader checks visible boxes before normal page-turn and menu zones, gives links priority, and lists each intersected annotation once. A single annotated passage opens its note directly. Reader displays notes as plain text. KOReader also offers rich note formatting and per-highlight line styles and colors. [Tap precedence and hit testing](https://github.com/koreader/koreader/blob/v2026.07.1/frontend/apps/reader/modules/readerhighlight.lua#L290-L311) · [Overlap chooser, note viewer and highlight actions](https://github.com/koreader/koreader/blob/v2026.07.1/frontend/apps/reader/modules/readerhighlight.lua#L1260-L1420)

## Fixed-page book map

KOReader draws chapter spans, page slots and annotation markers in its book map. Its status bar reads the active contents ticks, including handmade chapters. Reader’s fixed-page map now uses the same publisher or custom chapter boundaries as its status bar. It draws a grid of page ranges for the entire document, narrows a range to individual pages, and marks the current page, bookmarks and highlights. Choosing a page records one return location. Browsing ranges or closing the map preserves the current page. The PDF progress bar and remaining-page count immediately follow a change of contents. ## Implementation order

1. **Selection, dictionary and note navigation.** Start with a linked note and two small dictionaries in an authored EPUB. Compare the action surface, each nested back step, the exact anchor, the selected quotation and saved result state. Repeat the selection subset on embedded PDF text and OCR.
2. **Landscape and bottom typography.** Verify viewport transforms, input geometry and RTL spread order in each supported orientation. Compare the remaining typography controls under the same fonts and dimensions.
3. **Contents, book map and footer.** Give each consumer the same effective chapter list, test custom and publisher outlines, then add depth, chapter-length and progress preferences. Check sparse outlines and mixed front matter.
4. **Provider and system verification.** Run the path matrix on EPUB, PDF and DjVu. Capture each visible overlay using an authored book. Include callbacks, exact saved locations, framebuffer checks and separate observations for physical buttons and e-ink refresh. A screenshot alone cannot establish persistence or gesture behavior.
