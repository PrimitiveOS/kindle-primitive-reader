# Reader requirements

Reader is a standalone, Kindle-first PrimitiveOS application. **The active goal is to match KOReader's core Kindle reading workflows** with an original e-ink interface and a Rust application core: open and render supported documents; navigate and adjust reading layout; search and look up information; manage bookmarks, notes, highlights and reading progress; support accessibility and offline scan reading; and keep local reading data portable. A general extension/plugin system, Terminal or shell, and unrelated utility tools are outside this goal. Each requirement below defines behavior to verify. The stages describe planned scope and carry no implementation, device compatibility, or publication claims. See [architecture](architecture.md), the [scope and completion checklist](reading-parity-plan.md#scope-and-completion-checklist), and the [execution plan](execution-plan.md).

## Product scope

- Start with the jailbreak-enabled Kindle Oasis 3 on firmware 5.18.2 and ARMHF. Treat each additional Kindle model and firmware combination as a separate verification target. Use the established Launcher entry, foreground session, and USB handoff. [PrimitiveOS hardware and workflow handoff](https://github.com/PrimitiveOS/kindle-primitive/blob/main/docs/handoff/STATE.md) · [PrimitiveOS package contract](https://github.com/PrimitiveOS/kindle-primitive/blob/main/docs/contracts.md)
- Give the reading surface priority. Show compact controls on demand, use touch and the physical page-turn buttons on supported hardware, and keep essential controls reachable in either portrait orientation. Exit back to the correct host and permit normal device sleep.
- Open local, DRM-free publications and user-provided files. Core reading, search, annotation, and dictionary workflows work offline. Ordinary password-protected PDFs have their own support check. The comparison covers books available as local files.
- Build original code, screens, artwork, and test fixtures. Use KOReader's documented and observable workflows as the reference. Evaluate every dependency, asset, font, dictionary, and OCR data set before distribution. Keep any reference installation and its files separate from Reader. [KOReader guide](https://koreader.rocks/user_guide/) · [KOReader source and license](https://github.com/koreader/koreader)
- Kindle is the product platform. The desktop simulator supports development and repeatable tests. Android, Kobo, PocketBook, Cervantes, desktop product releases, KOReader's Lua plugin ABI, user patches, and compatibility with the full KOReader plugin catalogue are outside the parity target. Individual reading workflows can be implemented natively in Reader without adding a plugin host.
- Do not build a general extension/plugin runtime, plugin manager, or third-party extension catalogue. File extensions are still used to identify supported reading formats.
- Terminal and shell access, RSS/news downloading, HTTP inspectors or servers, patch management, online book acquisition, remote progress/annotation services, Wikipedia article-to-EPUB export, and unrelated developer utilities are out of scope. Contextual Wikipedia and translation actions from selected or visible reading text remain in scope, require explicit confirmation before sending text, and must return to the same reading location when dismissed. Local dictionaries and reading-data export/import work offline. Wi-Fi, battery, clock, sleep, wallpaper, and other Kindle-wide controls remain with Launcher.
- Prioritize document opening and rendering, reading navigation and layout, local search and lookup, bookmarks, notes and highlights, reading progress, offline scan tools, accessibility, and local reading-data migration.

**Completion rule:** the goal tracks K01–K20 and K23–K24. An excluded KOReader
module or menu item is closed scope, not an open gap or a completion blocker.
Source inventories and captured menus are evidence for comparison, not a
requirement to reproduce every listed control.

## P0 · EPUB feasibility

Demonstrate that the proposed EPUB rendering and application stack can meet the hardware, layout, and licensing needs of a native reader.

| ID | Reader requirement and KOReader workflow | Acceptance evidence |
| --- | --- | --- |
| K01 | Open local reflowable EPUB 2 and EPUB 3 through a candidate renderer. Resolve package metadata, manifest, spine, XHTML, publisher styles, internal links, and embedded images within a declared support subset. | Open at least one licensed fixture for each EPUB version. Verify chapter order, a linked footnote and return, styled text, and an image opened from the archive. Compare the results with the agreed fixture expectations and record unsupported media, styles, and layout features. |
| K02 | Paginate at device dimensions and retain a document-relative text location through repagination. | Read to a marked passage inside a chapter, save, rotate, and change text size. Each completed repagination contains the marked passage on the active page. Reopen and reach the same passage. Repeat with two instances of the same phrase in the chapter to detect ambiguous anchors. |
| K03 | Page forward and backward by touch and physical buttons. Respect the PrimitiveOS foreground session, e-ink refresh, suspend and resume, USB handoff, and normal exit. | On Oasis 3, test both portrait orientations and both physical buttons. Check for duplicate turns after a single press and input arriving after an app switch. Leave the app open across sleep and wake, exercise the established USB workflow, then exit to the expected host and confirm touch responds there. |
| K04 | Constrain parsing, image decoding, prefetch, and cached pages to a workable device budget. Present errors and permit recovery from malformed and unsupported inputs. | Report cold-open time to first readable page, steady-state page-turn latency, peak resident memory, and cache behavior for the prototype and KOReader on the same device and corpus. Verify that a large chapter, an image-heavy book, and a truncated file preserve navigation or an actionable exit. Establish explicit budgets using these measurements before accepting the prototype. |
| K05 | Build an original Rust application and account for all dependencies and bundled materials. Produce a reproducible ARMHF build input and record the dependency and toolchain choices. | An independent checkout can run the documented locked build and identify the executable's target architecture, runtime libraries, and inputs. Record component licenses, linking and redistribution terms, and obligations for the exact configuration. Resolve distribution compatibility before adopting a component for a release. |

The [EPUB 3.3 publication specification](https://www.w3.org/TR/epub-33/), [EPUB 3.3 reading systems specification](https://www.w3.org/TR/epub-rs-33/), and [EPUB Canonical Fragment Identifiers](https://idpf.org/epub/linking/cfi/) define useful conformance and location references. Tests over a declared subset establish that subset's behavior. A full EPUB conformance claim requires separate evidence.

| K10 | Search the text of the current book offline and jump to a result. ## P2 · Offline reading parity

Add common local formats and document controls that support reading without a network connection.

| ID | Reader requirement and KOReader workflow | Acceptance evidence |
| --- | --- | --- |
| K12 | Read fixed-layout PDFs with page and outline navigation, fit page or width, adjustable zoom, manual crop, rotation, and continuous scroll or paged reading. Map physical page buttons to the active reading mode. | Open a small text PDF and a large scanned PDF. Test forward and back in both modes, width fit and cropping, rotated pages, and reopening at the last view. Inspect sharpness, page boundaries, memory, and responsiveness on Kindle. Verify the source PDF's hash is unchanged. |
| K13 | Extract and search embedded PDF text, open page links, and anchor text highlights and notes to page coordinates. Provide a clear outcome when a page has no text layer. | Search two PDFs with embedded text, including one with a rotated page. Select and annotate text, change zoom and crop, reopen, and verify the stored markup aligns to the text. Open a scanned page with no text and verify navigation and the appropriate feedback. |
| K14 | Read CBZ and supported image sequences with natural ordering, right-to-left option, fit and zoom, and a controllable e-ink refresh policy. | Open a fixture with pages named `1`, `2`, and `10`, and confirm numeric order. Reverse the reading direction, zoom in a spread, and verify the next/previous controls and resume position. Sample ghosting and memory on the Oasis after repeated turns through a large archive. |
| K15 | Look up selected words using documented local dictionary formats and offer contextual Wikipedia or translation for selected text or readable pages. Keep local dictionary lookup offline; require a deliberate provider action before sending text externally; preserve the selection and reading location on cancellation or dismissal. | With Wi-Fi off, query known and unknown words, edit the original query by tapping the dictionary pencil, edit the displayed result headword by long pressing it, submit a nested lookup, and verify Back restores the prior result and selection. Switch dictionaries and return to the selected passage; search the book from the contextual dictionary and verify the original selection is used for EPUB and PDF. With network access enabled, verify the preview sends no request until confirmation, both provider types return to the same anchor when cancelled, long translation text remains within documented limits, and local lookup still works after a provider failure. |
| K16 | Read common DRM-free reflowable alternatives such as TXT, FB2, and local HTML through format-specific adapters or an approved converter. | Publish the exact supported extensions and encoding limits. Open one structural fixture per supported format and verify headings, text order, image and link behavior where present, search, and position after reopening. Attempt an unsupported variant and verify a recoverable error. |

PDF, comics, dictionary, and format behavior references are in the [KOReader guide](https://koreader.rocks/user_guide/) and [KOReader format list](https://github.com/koreader/koreader#main-features).

EPUB interoperability includes books with a correctly identified root `mimetype` member written after another ZIP member or compressed by the packager. Reader validates the container, package and spine before opening the document. EPUB 2 PUBLIC and SYSTEM declarations in the container, OPF, NCX and XHTML can be read offline. The parser ignores external declarations, recognizes standard XHTML character names from its built-in table and keeps custom DTD processing disabled. The package test builds an original example, checks its contents link, finds the decoded sentence and renders a page. KOReader’s pinned engine likewise looks up the marker and container by member name. [Upstream EPUB detection](https://github.com/koreader/crengine/blob/b32a88ffbbf505cf2ea5208c1a49002d70d3609f/crengine/src/epubfmt.cpp#L78-L109) · [Reader package tests](../tests/epub_package.rs)

Reader can open an EPUB with a small zero-filled suffix after its ZIP footer. If the ZIP footer points to a displaced directory and member offsets have shifted, Reader checks the surviving directory against each local header and reconstructs offsets in memory. A missing reflowable chapter displays an explanation and can be turned past. The original spine indexes and progress weights are preserved. Opening a resource still enforces the extraction limit, exact length and CRC. The Library fingerprints the original bytes so repaired books retain reading positions across sessions. KOReader’s engine also retries with local headers when its ordinary archive index fails. [KOReader archive fallback](https://github.com/koreader/crengine/blob/b32a88ffbbf505cf2ea5208c1a49002d70d3609f/crengine/src/lvstream.cpp#L2626-L2680) · [Reader recovery tests](../tests/epub_package.rs)


## P3 · Advanced reading, formats and reading-data import

Expand advanced reading and migration workflows. Use capability-by-capability verification as the basis for parity claims.

This goal covers local reading features. K21 book acquisition and K22 remote
progress or annotation sync are excluded integrations; they are not planned
milestones or completion requirements. Keep their reserved IDs for traceability.

| ID | Reader requirement and KOReader workflow | Acceptance evidence |
| --- | --- | --- |
| K17 | Read DjVu and add scanned-page tools for supported PDF and DjVu variants. Cover deskew or auto-crop, multi-column reading order, reflow, and opt-in offline OCR as distinct capabilities. | Read single- and multi-column scans with known text order. Test crop and zoom reset, OCR selection against a known passage, and reflow at multiple font sizes. Exercise a missing OCR language pack, cancellation, and a large scan on Kindle. Record supported languages, formats, and observed limits. |
| K18 | Evaluate additional KOReader formats and enable those that pass dependency, resource, and fidelity gates. Investigate CBR/CBT, MOBI/AZW3 without DRM, RTF, CHM, and office or archive formats independently. | Maintain an explicit format and variant list with a support decision and evidence for each. For enabled readers, open representative files and verify reading order, key media, navigation, and resume. For unsupported formats, identify them and offer an explicit open-in route when an installed app handles them. |
| K19 | Extend EPUB fidelity to supported fixed-layout publications, complex scripts, hyphenation, bidirectional text, and advanced publisher styling. | Use documented fixtures for fixed pages, bidirectional passages, complex-script shaping, CJK text, and hyphenation. Verify rendering as well as selection, text search, link targets, and location stability. Publish the supported CSS, script, and media limits established by these fixtures. |
| K20 | Add advanced offline organization and reading controls. Candidate capabilities include collections, reading statistics, skim or page overview, configurable gestures, and reusable reading profiles. | Create and reopen collections containing overlapping books, restore a per-book reading profile, jump from an overview and return, and verify remapped gestures avoid accidental navigation. Compare the reading statistics to a controlled session that includes sleep. Test each supported capability independently. |
| K23 | Import supported KOReader reading positions, bookmarks, highlights, and notes from documented exports or recognized sidecar variants. Treat source data as read-only and preview possible matches and unresolved records. | Use copies of representative KOReader export and sidecar fixtures with missing books, duplicated titles, and established anchors. Preview, import twice, and verify deduplication and unresolved records. Compare source hashes before and after, and verify that a failed import can be retried safely. |
| K24 | Support user-selected file handlers and coexistence with Viewer and KOReader. **Reserved IDs outside this goal:** K21 (OPDS/calibre acquisition) and K22
(remote progress or annotation sync) are not part of the active checklist.
The [KOReader guide](https://koreader.rocks/user_guide/) documents the in-scope
workflows for OCR, profiles, collections, and local reading data. Support for
any imported file variant is determined by its fixture and documented limits.

## Verification and release evidence

- Keep a versioned corpus of project-authored or redistributable fixtures. Record format, fixture license, expected locations and screenshots or reference behavior. Use small targeted fixtures for edge cases and representative real books for performance and field checks.
- Record the app build, device, firmware, book or corpus revision, settings, and timing method with each result. For comparison with KOReader, use the same device, books, and comparable layout settings. Report cold and warm behavior separately, use repeated page turns, and identify whether a timing covers render completion or the physical display update.
- Run automated fixtures and desktop simulation before hardware verification. Reserve physical display, touch, physical buttons, battery and suspend behavior, USB, app handoff, and hardware performance claims for runs on the device. Record blocking failures and defer model support claims until the relevant checks pass.
- Maintain reproducible versioned release artifacts on GitHub when publishing completed builds. Record the GitHub release, package contents and checksums, device results for tested builds, and Store listing revisions. Leave first-time manual Launcher installation and existing library state undisturbed during Reader deployment. [PrimitiveOS publication workflow](https://github.com/PrimitiveOS/kindle-primitive/blob/main/docs/store-submit-app.md)
