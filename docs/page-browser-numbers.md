# Page Browser thumbnail numbers

The Page Browser **Grid** panel offers three **Thumbnail page numbers** modes: **None**, **Row start**, and **All**. Row start labels the first thumbnail in each visual row; All is the existing default. Thumbnail touch targets, the selected-page indicator, bookmark icons, and hidden-page indicators remain available in every mode. The original reading position is unchanged until a thumbnail is opened.

Changing the mode saves a choice for the current book. **Save number default** saves the displayed choice for books without their own choice. **Use default numbers** removes the current book's override, so it follows the Reader default again. Book settings are part of the library and follow its existing save, backup, merge, and rollback paths. The default is stored with Reader controls and follows the existing reading-backup behavior for those controls. Older data without these fields continues to show all page numbers.

KOReader's pinned [page-number modes](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/ui/widget/pagebrowserwidget.lua#L331-L366) and [Page Browser menu](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/ui/widget/pagebrowserwidget.lua#L1080-L1104) provide the reference. Reader presents labels inside its existing thumbnail controls instead of KOReader's side labels. This implementation still requires simulation, accessibility, and Kindle display and persistence validation.

For fixed-layout documents, the ribbon retains its existing whole-document mapping and chapter ticks. For reflow documents it shows a local stripe of pages in the currently browsed chapter, centered on its thumbnail focus. A tap focuses a page in the stripe; a horizontal ribbon swipe moves by one stripe. Empty slots at a chapter edge are not destinations. Page buttons can still cross chapter boundaries, and a long hold opens Book Map for the browsed chapter. Cross-chapter stripes, exact reflow outline spans and stock multilayer layout remain open. Mirrored layouts reverse the stripe. The reading position stays unchanged until a thumbnail is opened. This implementation requires behavioral, simulator and Kindle validation.

Grid's **Chapter levels** setting and its separate custom/publisher persistence remain available; its fixed-document chapter ticks still honor the selected depth. Reflow page stripes do not yet draw outline spans, so this setting does not change their page-slot markers. Full multilayer spans remain open. [KOReader depth control](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/ui/widget/pagebrowserwidget.lua#L1107-L1130).

The ribbon handle identifies the browsed page and a separate caret indicates the actual reading page when it is in the displayed stripe. Up to three previous and next locations are marked where they resolve within it. Canonical reflow anchors must resolve against the already loaded chapter, and repeated chapter paths and raw anchors are omitted. Legacy anchorless positions use the saved page only for the matching chapter. Nearby cues can overlap and none changes saved history or reading position. Fixed-page cues retain their existing behavior.

On the ribbon, gray marks indicate highlights, black marks indicate notes, and taller black marks indicate page bookmarks. Reflow cues use the loaded chapter layout, require resolvable canonical endpoints in order and omit cross-chapter and raw selections; legacy page-only bookmarks use the matching chapter and saved page. At most 512 saved marks are examined, with a shared per-draw estimate of line, block and element work also limiting anchor resolution. Later or unverifiable cues may be omitted, especially in large chapters. This is an estimated work cap, not a measured device latency bound. Fixed-page cues retain their existing behavior.

The existing cancellable raw-position verification worker continues to support thumbnail cues. Raw-position ribbon cues are omitted from the local reflow stripe; verification and cross-chapter stripe support remain open.

Thumbnails show a highlight icon on pages containing a saved highlight, or a note/edit icon when any highlight on the page also has a nonblank note. Fixed documents include continuation pages of multi-page selections. Reflow documents use the existing current or preview chapter layout and mark pages where a verified selection produces visible geometry; unresolvable anchors are skipped. To bound work on heavily annotated books, at most 512 reflow page/selection geometry checks are performed per draw, so later marks may be omitted from that thumbnail window. The existing bookmark indicator remains in the opposite corner, and thumbnail tap and hold actions are unchanged. This Reader-specific thumbnail cue was inspired by KOReader's highlight and note indicators on the page ribbon. Exact KOReader ribbon symbols and broader reflow cue coverage remain open, and the new cues still need simulation and Kindle validation.

For a canonical or raw highlight crossing chapter boundaries, the worker verifies the complete saved quote before the current thumbnail chapter may display a local fragment. It requires a verified source and font snapshot, unique chapter paths and no unsupported or recovered-placeholder chapters; unresolvable or empty chapter fragments are omitted. The visible local fragment is mapped from the current preview layout without changing the reading position or saved mark. The thumbnail view retains its existing limit of four cross-chapter checks per draw and a maximum span of eight chapters; failed, pending, or over-limit selections remain omitted. The worker checks cancellation between chapter layouts, enforces the saved-highlight text limit, and preserves ODT continuation separators. These changes need simulation and device validation.

The Grid panel's **Help** button explains the implemented thumbnail, page-button, edge-swipe and ribbon controls, visual cues, and settings. Back returns to Grid without changing the book or browser position. This follows the intent of KOReader's [Page Browser About and gestures help](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/ui/widget/pagebrowserwidget.lua#L1145-L1207); Reader's text describes its own behavior. The layout and translations still require simulation and Kindle validation.

The visible **Return to book** button closes the Page Browser and any nested Book Map/Page Browser stack, returning to the existing reading location rather than opening the browsed thumbnail. **Back** retains its normal one-level navigation. KOReader supports [closing parent browsers together](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/ui/widget/pagebrowserwidget.lua#L1209-L1220); Reader exposes a separate touch control for this action. The new control still requires simulation and Kindle validation.
