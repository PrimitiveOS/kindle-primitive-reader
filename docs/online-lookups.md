# Online lookups while reading

Hold a word and use **Wikipedia** or **Translate** in the selection grid. **Search** in the top reading bar also offers a typed Wikipedia topic and translation of the current page. The preview shows the text, destination language and service. A network request starts when the reader taps Search, Translate or Full article. Closing the sheet restores the passage and selection. PDF and DjVu page translation uses the text layer or a previously recognized page. Reflow uses the lines visible in the current viewport or spread.

Wikipedia uses the MediaWiki query API and plain-text extracts, with a versioned Reader user agent and project contact URL. Reader verifies server certificates and restricts requests to its built-in service URLs. A lookup accepts up to 6,000 bytes of text and a Wikipedia search accepts 150 characters. Very long articles report the display limit. Exporting articles to EPUB, alternate translation analyses and custom server URLs remain open. Google's endpoint is the one used by the tagged reference. Its availability and rate limits are controlled by the provider. [MediaWiki search](https://www.mediawiki.org/wiki/API:Search) · [TextExtracts](https://www.mediawiki.org/wiki/Extension:TextExtracts)

## Wikipedia images

**Search → Wikipedia settings** has two switches. **Show image in search results** includes the lead thumbnail in each visited result or full article. Turning it off pauses the additional-images option and preserves that option's saved value. **Show more images in full article** adds figures and gallery images from the opened article. Both settings default to On.

After the text appears, a separate process loads the permitted images for the lookup on screen. In search results the lead thumbnail appears beside the title. In a full article, one image appears in the top-right corner of each illustrated page. Text wraps beside it and returns to full width below it. Tap the image to show its title and caption. Hold it or tap **Open image** to inspect it. **Back** returns to the same article text and caption state. **Previous**, **Next**, a vertical swipe and the physical page buttons turn article pages.

Reader requests PageImages lead metadata with the text query and retries the original text-only query if the combined request fails. After opening a full article, it uses MediaWiki's parsed article to find additional figures and galleries. The lead comes first, figure images follow in document order, then gallery images. A matching lead figure supplies its caption. The existing three-result limit still applies. [MediaWiki PageImages](https://www.mediawiki.org/wiki/Extension:PageImages#API) · [MediaWiki parse API](https://www.mediawiki.org/wiki/API:Parsing_wikitext)

Images use PNG, JPEG or WebP thumbnails served by `https://upload.wikimedia.org/wikipedia/`. Reader caps each response at 384 KiB and each full article at four loaded images. The worker accepts dimensions up to 2,048 pixels on each side and produces a grayscale image up to 480 pixels on each side. It has a five-second limit per request, refuses redirects and retains images in memory for the open lookup. Image arrival reflows the same source text and keeps the previous page's first source byte visible. A refused source, empty result, timeout or cancelled image process leaves the text available.

The pinned KOReader fixture executes both default-on switches, dependent enablement, lead-first ordering and the contextual article widget's one-image-per-screen-page flow. Its tap callback toggles the image caption. In Reader, the image inspector uses the same bounded still raster already received for the article. Stock can request a larger image and display animation in its separate inspector. ## Verification

Run `cargo test --locked --lib online` and `cargo test --locked --lib selected_wikipedia`. The tests cover request encoding, URL host validation, result ordering, Unicode chunk boundaries, romanization response parsing and preference persistence, provider failures, process cancellation, touch selection, hardware pagination, local history and restoration of the reading anchor. To regenerate the following screenshots, set `PRIMITIVE_READER_LOOKUP_SCREENSHOTS` to an output directory before running the tests. The on-screen passage and provider response are synthetic fixtures. Live HTTPS checks on the Mac separately returned three Wikipedia results for “E-paper” and a MyMemory English-to-Vietnamese translation. The Google endpoint returned HTTP 429 during the live check.
