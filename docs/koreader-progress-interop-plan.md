# KOReader progress protocol: audit and execution plan

This is a source audit and proposed implementation plan, dated 2026-11-22. No KOReader account was created or contacted, no server was deployed, and no new Reader sync implementation or interoperability test is claimed. Reader's existing [WebDAV progress sync](progress-sync.md) remains a separate working provider.

The reference is KOReader commit `9192014d8bd82a91dc1012473be0f238dedfdb54` (`v2026.07.1`), its base `6e4bc81af4e04f78d81677a323a780a71b29702a`, and CREngine `b32a88ffbbf505cf2ea5208c1a49002d70d3609f`. Reader was inspected at `991e879a019ba34d22fcb36464d12bb3d16966a4`. The client and API specification establish the wire contract below; the sync-server implementation is not part of these pinned sources. Server persistence, timestamp generation and production-specific behavior still require their own checks.

## Protocol contract

| Concern | Pinned behavior | Reader consequence |
| --- | --- | --- |
| Default service | `https://sync.koreader.rocks:443/`; a custom base URL is configurable. | Offer a distinct KOReader provider and explicit configuration; selecting it or editing settings must not contact the default service. |
| Media type | `Accept: application/vnd.koreader.v1+json`; JSON request/response middleware. | Send the exact accepted media type and JSON bodies. Verify content type and base-path joining against the actual pinned client. |
| Registration | `POST /users/create` with JSON `username`, `password`; the UI passes lowercase hexadecimal MD5 of the entered password as `password`. Client success is HTTP 201; the spec also lists 402 as a handled response. | Use an explicit Register action; never register while saving settings. Implement from the protocol facts, without copying Lua implementation. |
| Authorization | `GET /users/auth`; headers `x-auth-user` and `x-auth-key`, where the key is the same password MD5. Client success is HTTP 200; 401 is rejection. | This key authenticates requests and must be protected like the original password. HTTPS for public hosts; no header/secret logging or command arguments. |
| Push | `PUT /syncs/progress` with `document`, string `progress`, numeric `percentage`, `device`, `device_id`, and optionally `metadata`. Success is exactly HTTP 200 in the client. The API lists 202, but the client does not acknowledge it as success. | Validate bounded fields and finite percentage; do not treat 202 as a durable acknowledgement without a separate provider decision. |
| Pull | `GET /syncs/progress/:document`; success HTTP 200. The consumed body fields are `percentage`, `progress`, `device`, `device_id`, optional `timestamp`. | Bound and validate the response before preparing any local navigation. A body without `percentage` means no saved progress to the stock UI. Do not invent fields, timestamps or a successful destination. |
| Metadata | Off by default; optional object contains filename, displayed title and authors. | Keep metadata off by default and omit it entirely when off. Initial interoperability tests use authored books and identities. |
| Timeouts | Auth connect/total settings 5/10 seconds; progress 2/5 seconds. | Use a cancellable worker, bounded response and request deadlines; retain the existing lifecycle cancellation and local-reading behavior. |
| Conditional update | No ETag, revision, `If-Match`, or compare-and-swap field in this client protocol. | Keep WebDAV conditional-write guarantees scoped to WebDAV. A fetch-before-push can show a choice but cannot remove a subsequent KOReader-server race. |
| Clear/delete | No remote clear or delete method in `api.json` or the plug-in. | Do not encode a clear as an empty/foreign `progress`. Keep native WebDAV clear unchanged; KOReader provider shows remote clearing as unsupported by this protocol. |
| Logout | Removes the local `userkey` and clears its queued updates. No server logout/delete request occurs. | Sign out cancels owned work and erases this provider's local key/queue/comparison state; it must not erase WebDAV credentials or shared reading data. |

Primary source: [API specification](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/plugins/kosync.koplugin/api.json) · [Headers, timeouts and response handling](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/plugins/kosync.koplugin/KOSyncClient.lua#L1-L179) · [Register/login/logout](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/plugins/kosync.koplugin/main.lua#L560-L648).

### Document identity

Stock's default Binary matching reads `partial_md5_checksum` from the book's saved settings. If absent, ReaderUI calculates it through `util.partialMD5`. This is **not** the full-file MD5 or Reader's SHA-256 edition identity. The algorithm hashes up to 1,024 bytes from each of these offsets, in order, stopping when a read returns no data:

`0, 1024, 4096, 16384, 65536, 262144, 1048576, 4194304, 16777216, 67108864, 268435456, 1073741824`.

The initial zero results from LuaJIT's 32-bit shift behavior for the source loop's `i = -1`; do not reproduce it with an invalid Rust negative shift. A short read contributes its actual bytes. Repeated/overlapping behavior and EOF must be verified against the real Lua function with authored byte patterns, not a second copy of the proposed Rust algorithm. The optional Filename method hashes the exact basename, including extension and case, without its directory. This allows different content with the same basename to share a namespace; the UI should explain the user's choice. [Digest and metadata selection](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/plugins/kosync.koplugin/main.lua#L666-L703) · [Partial hash algorithm](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/util.lua#L1111-L1128) · [Saved checksum initialization](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/apps/reader/readerui.lua#L497-L502).

A new KOReader provider must calculate/cache this identity separately without changing Reader's existing edition keys, anchors, local saved positions, WebDAV resource names or backups. Changing server/account/matching method invalidates only its own pending requests and comparisons. A file change must invalidate the computed digest. Importing an existing KOReader sidecar checksum is a separate optional action, since a stale cached stock checksum may differ from the current bytes.

### Position identity is the main interoperability gate

Fixed-page stock documents push the top source page as a **one-based decimal string**. Reflowed documents push CREngine's current **XPointer**, not a percentage, EPUB CFI, HTML fragment identifier or Reader anchor. Stock floors percentage to four decimal places using `floor(value * 10000) / 10000`. Page-view percentages depend on its own page count; scroll-view percentages depend on its document height. These values are advisory for a different engine and must not substitute for an exact source location. [Fixed page](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/apps/reader/modules/readerpaging.lua#L168-L177) · [Reflow XPointer](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/apps/reader/modules/readerrolling.lua#L413-L415) · [Reflow percentage](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/apps/reader/modules/readerrolling.lua#L504-L512) · [Percentage rounding](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/frontend/optmath.lua#L18-L20).

Modern CREngine normalized XPointers use named element/text-node paths, same-name sibling indices, and a text point offset in its `lString32` text model. This offset counts that model's 32-bit characters, **not UTF-8 bytes**. Normalization skips internal boxing nodes and pseudo-elements; older requested DOM versions use V1 paths. EPUB import wraps every spine item in a stable `DocFragment`, including unsupported entries, and can create SVG wrappers or parser-repaired HTML. The path therefore cannot be fabricated by prefixing Reader's block ordinal. [XPointer parser](https://github.com/koreader/crengine/blob/b32a88ffbbf505cf2ea5208c1a49002d70d3609f/crengine/src/lvtinydom.cpp#L11356-L11439) · [Normalized path writer](https://github.com/koreader/crengine/blob/b32a88ffbbf505cf2ea5208c1a49002d70d3609f/crengine/src/lvtinydom.cpp#L11541-L11623) · [Version selection](https://github.com/koreader/crengine/blob/b32a88ffbbf505cf2ea5208c1a49002d70d3609f/crengine/include/lvtinydom.h#L1802-L1812) · [EPUB spine wrapping](https://github.com/koreader/crengine/blob/b32a88ffbbf505cf2ea5208c1a49002d70d3609f/crengine/src/epubfmt.cpp#L1846-L1924).

Reader currently keeps canonical UTF-8 block offsets, legacy text-model projections and element/fragment owners. It does not retain a proven CREngine-compatible normalized text-node map. Transport completion alone cannot close this gap. Never send Reader's serialized anchor as `progress` to a KOReader namespace, and never silently open an approximate percentage when an incoming XPointer does not resolve.

## Stock comparison and conflict behavior

Stock ignores a pull from the same `device` and `device_id`, or one with equal rounded percentage **or** equal progress string. An explicit manual Pull applies a differing server position immediately. Automatic pulls compare server `timestamp` with the last local page-turn wall-clock timestamp; when no server timestamp exists they compare percentage. Their forward/backward policies are Prompt, Auto and Disable, defaulting to Prompt/Disable. With a timestamp, “forward” means newer activity rather than necessarily a numerically later page. There is no three-way common-baseline comparison in this plug-in. [Pull policy](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/plugins/kosync.koplugin/main.lua#L812-L940).

Automatic sync starts off. When explicitly enabled, hooks include book close, page turns, resume, suspend, network connected and disconnecting. The non-interactive push/pull debounce is 25 seconds; page-count pushes wait 10 seconds after the latest page event. The offline queue keeps the latest entry per document per UTC-sized day bucket, expires entries after 28 days and caps itself at 200. Its current drain acknowledges successful scheduling through `pcall`, not the later HTTP callback. That is a source-observed reliability limitation, not a behavior to reproduce: a Rust queue should retain an item until an actual successful reply, stop on auth rejection, and remain scoped to its original account. [Defaults](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/plugins/kosync.koplugin/main.lua#L44-L67) · [Lifecycle hooks](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/plugins/kosync.koplugin/main.lua#L942-L1116) · [Queue](https://github.com/koreader/koreader/blob/9192014d8bd82a91dc1012473be0f238dedfdb54/plugins/kosync.koplugin/KOSyncQueue.lua#L1-L108).

The existing native WebDAV provider uses an acknowledged baseline and strong ETags, handles versioned clears, and does not rely on a remote clock. Its policy stays intact. A KOReader account needs distinct, accurately labeled manual push/pull behavior and a separate opt-in automatic policy. Do not present WebDAV conflict/clear guarantees as properties of the KOReader server.

## Bounded implementation sequence

1. **Protocol and identities.** Add an independently written `kosync` wire module using the already pinned MD5 and HTTP crates. Implement strict bounded request/response types, explicit Register/Authorize/Pull/Push operations and the exact digest functions. Preserve unknown harmless response fields for forward compatibility only when safely ignored. Reject wrong types, non-finite/out-of-range percentage, invalid page/XPointer, oversized bodies, credential control characters, redirects and unsupported URL forms. Keep the existing worker stdin transport, owned cancellation, private atomic configuration and public-HTTPS/local-HTTP rules. Gate this phase with an authored localhost server and the immutable stock client; no owner books or real accounts.
2. **Separate account and UI.** Add a provider choice to the existing compact Progress sync controls. Keep `progress-sync.json` byte-compatible for WebDAV and introduce a separate private `kosync.json` for KOReader credentials/account settings; selecting a provider does not turn it on. Keep username/key/queue outside the backup component allowlist, exports, screenshots and payloads. Preserve WebDAV settings and its clear action when switching. Add visible Register, Sign in, Sign out, Push and Pull controls with shared icons/pressed feedback. Show the provider's available format and remote-clear limits before a request is possible.
3. **Fixed-page interoperability.** Enable PDF first, with validated one-based source pages, exact document matching and retained local zoom/crop settings. Prepare/validate a remote position before mutation; persist and open it transactionally, retaining a return position. A response for an old book/account must not mutate the current book. Verify stock → Rust → stock using two distinct device IDs and a real stock client against an authored local server. Other fixed formats require their own shared page-identity checks rather than automatic enablement.
4. **Reflow XPointer adapter.** Create a bounded, optional source-node projection for well-formed EPUB spine items. Preserve canonical bytes, source revisions, anchors and legacy projections. Bind the map to exact source input and a declared stock DOM contract. Support proven element/text sibling indices, Unicode-scalar offsets and spine fragment wrappers; refuse unproven repaired/legacy/wrapped inputs. Before enabling any reflow send/pull, compare both directions against the actual frozen native CREngine API. Expand coverage by proven case, not by converting unknown positions to percentages. MOBI/AZW3, FB2, HTML and other providers stay disabled until their independent DOM/import mappings pass.
5. **Automatic policy and durable retry.** Only after exact-position interchange passes, add independent explicit automatic opt-in with the stock Prompt/Auto/Disable strategies and documented clock behavior. The kit continues to own sleep, USB and network controls; an app must not take over those systems. Queue only acknowledged-needed updates, retain until HTTP success, bound by account/document/date/count and cancel on sign-out. Test failures and restart before enabling lifecycle hooks. Keep manual-only availability honest while this phase is pending.
6. **Combined acceptance and publication.** Run unit/functional/system checks, actual-worker local-server tests, desktop screenshots in both themes and unchanged-source reopen checks. Repeat native Kindle acceptance when reachable, then publish tested source/build through the normal release process. Do not mark direct KOReader interoperability complete based only on protocol-shaped JSON, a shared digest, an approximate destination or the existing WebDAV tests.

## Required test matrix

| Layer | Meaningful checks |
| --- | --- |
| Protocol oracle | Record actual pinned client requests to an authored loopback server: registration MD5, auth headers, Accept/content type, path/base-path escaping, push progress string, optional metadata omitted/present, pull body, HTTP 200/201/202/401/402/404/429/500, malformed JSON and truncated/oversized replies. No external network. |
| Hash oracle | Compare Rust against actual `util.partialMD5` for empty, 1/1023/1024/1025/2048/4096-byte authored patterns, each sampled boundary and a sparse large file; mutations inside/outside sampled ranges; basename case/extension/Unicode/rename. Keep native SHA-256 identity unchanged. |
| Two-client fixed | Stock client A pushes page, Rust B resolves exact page, B changes zoom/font-independent local settings and pushes another page, stock A pulls same page; same-document renamed paths, wrong bytes/matching mode, page 0/out of range, same-device response and lost PUT reply. Verify original files unchanged. |
| Reflow oracle | Authored multi-spine EPUB including nonlinear/unsupported spine entries, nested inline siblings and adjacent text nodes, whitespace/NBSP, numeric C1 compatibility, combining/astral characters, ruby, image boundaries, hidden elements and SVG wrappers. Capture actual native XPointer ↔ decoded text-node offset ↔ Reader anchor in both directions. Repeat after font/layout changes and restart. Explicitly refuse an unsupported DOM instead of moving elsewhere. |
| Conflict/retry | Manual pull versus current device; equal percentage but different source passage; equal passage but different layout percentages; server timestamp absent/newer/older, backward clock, simultaneous pushes, queued outage/auth rejection/202/late callback, account/server/matching changes, cancelled worker, sleep/USB/exit and process restart. Distinguish provider races from native ETag semantics. |
| State/UI/privacy | Existing WebDAV accounts and clears still work; backup/export excludes both providers' secrets/queues; persisted config is private and atomic; failed navigation/save retains old frame/page; visible Back/Cancel and pressed-state rectangles; no password/key/title in screenshots or logs; no request occurs from opening settings or ordinary reading with sync off. |

The first proposed deliverable is protocol-oracle evidence plus fixed-page interoperability. Reflow acceptance remains contingent on the separate XPointer adapter and native source-position oracle. No new package dependency, data import, feature completion or native acceptance follows from this plan alone.
